# Contributing

## Workflow

1. Branch from `main`: `feat/<name>`, `fix/<name>`, `docs/<name>`, `test/<name>`, `chore/<name>`
2. Conventional commits — `<type>: <subject>`, lowercase, imperative, no period, ≤72 chars; body explains *why*
3. All gates green before merge:
   - Rust (repo root): `cargo fmt --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace -q`
   - Frontend (`frontend/`): `pnpm build && pnpm lint && pnpm test && pnpm e2e`
   - Postgres changes: the `pg-tests` feature against the compose db (see `docs/DEVELOPMENT.md`) and a refreshed `.sqlx/`
4. No AI attribution lines in commit messages (a `prepare-commit-msg` hook strips them — do not bypass it with `--no-verify`)

## Dependencies

- Cargo: add via `cargo add`; `Cargo.lock` is committed; a new crate (and any new transitive entry) must be ≥7 days old on crates.io — force exact versions with `cargo update --precise <ver> -p <crate>` when the newest release is younger
- pnpm only (never npm): exact pins; `pnpm-lock.yaml` committed; `frontend/pnpm-workspace.yaml` enforces `minimumReleaseAge: 10080`
- `frontend/src/components/ui/` is shadcn-registry-owned: add with `pnpm exec shadcn add <name>`, never hand-edit

## Clinical content and data

- Synthetic data only — never commit real patient data. Demo data is regenerated by the scripts in `scripts/` (see `demo/PROVENANCE.md`); keep the provenance and `crates/api/tests/demo_data.rs` in step with any change
- Analyte data (CVI, CVA, intervals, thresholds) lives only in `crates/drift/src/profiles.rs`, each value with its source; bump `REVIEWED` when changing one
- `crates/drift` stays pure (no IO, no clock); every detector change comes with scenario tests
- The review audit is append-only by design — never add update/delete paths
